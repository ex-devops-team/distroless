## Purpose

Воспроизводимый сбор метрик размера контейнерных образов и количества уязвимостей с агрегацией в сравнительный отчёт по вариантам runtime.

## ADDED Requirements

### Requirement: Image size measurement
Система MUST измерять размер каждого собранного образа эксперимента в байтах (как минимум размер локального образа после сборки; дополнительно допускается сжатый/registry size, если он доступен тем же инструментом). Результат MUST быть привязан к тегу/идентификатору образа.

#### Scenario: Size recorded for each image
- **WHEN** оператор запускает замер размера для собранного образа из матрицы
- **THEN** в результатах появляется запись с идентификатором образа и размером в байтах

### Requirement: Vulnerability scan
Система MUST сканировать каждый собранный образ на известные уязвимости с помощью **Grype** и фиксировать количество находок как минимум по severity CRITICAL, HIGH, MEDIUM, LOW (и TOTAL при наличии). Версия Grype и идентификатор/дата vulnerability DB MUST быть зафиксированы в отчёте или метаданных прогона, чтобы результат был интерпретируем.

#### Scenario: CVE counts by severity
- **WHEN** оператор запускает сканирование уязвимостей Grype для образа из матрицы
- **THEN** в результатах появляются счётчики как минимум для CRITICAL и HIGH, связанные с идентификатором образа

### Requirement: Comparative report
Система MUST формировать сравнительный отчёт (markdown), где для каждой строки матрицы указаны: язык, вариант, размер, счётчики CVE по severity. Отчёт MUST обновляться воспроизводимой командой прогона эксперимента.

#### Scenario: Report covers full matrix
- **WHEN** оператор выполняет полный прогон замера после успешной сборки всех вариантов
- **THEN** отчёт содержит строку для каждого варианта матрицы с полями размера и CVE

### Requirement: Smoke validation before metrics
Перед включением образа в отчёт система MUST (или оператор через тот же прогон) подтвердить, что контейнер отвечает на HTTP health/root endpoint. Образы, не прошедшие smoke-check, MUST NOT попадать в итоговый отчёт как успешные измерения (допускается отдельная пометка failure).

#### Scenario: Failed smoke excludes success row
- **WHEN** образ собран, но smoke HTTP-check завершается ошибкой
- **THEN** итоговый успешный сравнительный отчёт не представляет этот образ как валидное измерение без указания failure
