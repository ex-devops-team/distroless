## Context

См. мотивацию в `proposal.md`. В текущей реализации benchmark baseline-образы для части языков использовали Ubuntu/slim, а distroless — Debian 12, что делает сравнение CVE по severity частично несопоставимым из-за разных advisory-источников и правил нормализации severity.

## Goals / Non-Goals

**Goals:**
- Обеспечить парное сравнение baseline vs distroless в одной distro-линейке.
- Зафиксировать это правило в матрице, Dockerfile-подборе и отчёте.
- Перегенерировать отчёт с пометкой сопоставимости пары.

**Non-Goals:**
- Полная унификация severity между разными сканерами.
- Расширение эксперимента на новые языки или multi-arch.
- Переписывание логики benchmark вне задач согласованности distro lineage.

## Decisions

### 1) Базовая линия сравнения: Debian-first
- Для пар baseline/distroless выбираем Debian 12 как основную линию, т.к. distroless runtime в эксперименте уже Debian 12.
- Если для конкретного языка baseline на Debian технически недоступен/нерелевантен, это фиксируется явно в отчёте как ограничение.

**Альтернатива:** Ubuntu-first для baseline и смена distroless эквивалентов — отвергнута, так как текущие distroless теги естественно привязаны к Debian.

### 2) Матрица образов должна хранить lineage
- Каждая строка матрицы получает поле `distro_lineage` (например `debian12`).
- Для пары baseline/distroless рассчитывается флаг сопоставимости (`comparable=true/false`).

### 3) Отчёт разделяет «данные» и «интерпретацию»
- Данные по всем образам публикуются.
- Финальная интерпретация baseline vs distroless допускается только для пар с одинаковой lineage.

## Risks / Trade-offs

- [Некоторые baseline-образы всё равно тянут другие пакеты и CVE-поверхность] → Сравнивать тренд по парам и явно документировать образ-источник.
- [Дробление на comparable/non-comparable усложняет отчёт] → Добавить простое поле/пометку в таблицу и короткое объяснение в заголовке отчёта.
- [Смена баз может поменять абсолютные цифры CVE] → Ожидаемо; это и есть цель коррекции методики.

## Migration Plan

1. Обновить матрицу образов и Dockerfile-базы под Debian-first.
2. Обновить скрипт отчётности: lineage + флаг сопоставимости пары.
3. Перезапустить benchmark.
4. Сверить, что финальные выводы делаются только по сопоставимым парам.
